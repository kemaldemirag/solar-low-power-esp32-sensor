# Engineering Rules — 15.09.2026

1. Do not invent client files, measurements, test results, certifications, approvals or hardware access.
2. Do not mark requirements VERIFIED without evidence paths.
3. Record assumptions and OPEN items instead of guessing engineering values.
4. Prefer scripts and reproducible calculations over manually typed final numbers.
5. Keep source-job requirements traceable to derived portfolio requirements.
6. Preserve boundaries between design, simulation, fabrication, bench validation and field validation.
7. If a toolchain is unavailable, create the design/test plan and mark execution BLOCKED rather than fabricating output.
8. Record major architecture changes in a decision register.
9. Individual subsystems must be testable before optional cross-project integration is attempted.
