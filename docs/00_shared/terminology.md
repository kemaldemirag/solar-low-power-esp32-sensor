# Terminology — 15.09.2026

## Requirement status
- **OPEN** — requirement/action not yet implemented or proven.
- **IN_PROGRESS** — work has begun but is incomplete.
- **IMPLEMENTED** — design/code/artifact exists, but verification may still be absent.
- **VERIFIED** — evidence-backed verification exists.
- **BLOCKED** — execution cannot continue because a dependency/tool/input is unavailable.
- **NOT_APPLICABLE** — requirement is explicitly out of scope with rationale.

## Hardware status
- **DESIGNED** — engineering design exists.
- **SIMULATED** — simulation evidence exists.
- **FABRICATED** — physical hardware has been manufactured.
- **ASSEMBLED** — physical assembly exists.
- **BENCH_TESTED** — bench evidence exists.
- **FIELD_TESTED** — field evidence exists.

## Portfolio-ready
Requirements are traceable, architecture documented, calculations/build steps reproducible, validation explicit, evidence paths present for every VERIFIED claim, limitations disclosed, and README independently understandable.
