4. **DEC-11 — still BLOCKED.** No quiescent-current evidence found for any remaining OVP candidate; re-affirmed BLOCKED rather than a speculative selection, per instruction.

**GATE-2 status: BLOCKED.**

Closing the four named contracts did not clear the gate — it surfaced three additional problems more fundamental than the original four, via the batch-3 Drive-relayed research:

1. **DEC-01/DEC-02 REOPENED.** MCP73871 has one physical input, not two; the "no external arbitration needed" premise behind the current solar+USB topology is false. No external mux/ORing component has been selected.
2. **DEC-04 REOPENED.** TPS7A02 (200 mA max) cannot supply the ESP32-WROOM-32E's active/WiFi-TX current (≥0.5 A recommended, ~379 mA peak measured). No active-mode regulator has been selected; TPS7A02's role is now sleep-only, provisionally.
3. **DEC-12 (new).** The interface contract's power-gating design (sensor rail gated, pull-ups implicitly on an always-on rail) matches a condition BME280's datasheet explicitly forbids (I2C pins held high while VDDIO is off — ESD-diode overcurrent, permanent-damage risk). Not yet fixed in `04_interface/i2c_interface_contract.md`.
4. **DEC-13 (new).** No independent battery-side protection component selected (GAP-03's outcome-B follow-up).

None of these four are resolved. PCB/firmware implementation (P01-08) does not open. This session does not proceed to it, and per the 17.09 baseline, GATE-2 is not re-evaluated again until DEC-01/DEC-02, DEC-04, DEC-12 and DEC-13 each reach their own documented closure.
